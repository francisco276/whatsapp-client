# Fix: asignación de admin aditiva e idempotente

Archivos modificados:
- `src/controllers/workspaces.ts` (handler `join`)
- `src/services/WorkspacesManager.ts` (`createWorkspace`)

## Qué cambia

La asignación de admin ahora gira en torno al flag `isAdmin` de monday (el
`context.user.isAdmin` que manda el frontend), no a "quién abrió primero".

| Situación | Antes | Ahora |
|---|---|---|
| Admin real de monday abre la app | Solo admin si abría primero | **Siempre** queda admin (si no tiene record ya) |
| No-admin abre primero (workspace nuevo) | **Se volvía admin** (bug Salvador) | Queda pendiente; NO se vuelve admin |
| Admin real abre después de que alguien tomó admin | "No auto-join" (no podía registrarse) | **Se registra como admin** |
| Usuario con record existente abre | Sin cambios | Sin cambios (record intacto) |
| Workspace nuevo creado por `join` | Creador = admin automático | Creación NO otorga admin por sí sola |

Garantías:
- **Nunca borra ni degrada** un record existente (`onConflictDoNothing`).
- **Aditivo**: cada instalación/apertura solo puede *agregar* el record del usuario actual.
- **Multi-admin**: cualquier admin de la cuenta puede ser admin de la app; no se pisan entre sí.

## ⚠️ Dependencia del frontend (IMPORTANTE)

El backend ahora **depende de que el frontend mande `isAdmin`** en el body del `POST /workspaces/join`:

```js
const context = await monday.get('context')
await fetch('/workspaces/join', {
  method: 'POST',
  body: JSON.stringify({
    workspaceId: String(context.data.account.id), // el accountId = work
    isAdmin: Boolean(context.data.user.isAdmin)    // <-- esto debe ir
  })
})
```

Si el frontend NO manda `isAdmin`, todos se tratan como no-admin y **nadie**
se auto-asigna admin (quedarían "pending"). En ese caso siembras el primer admin
por SQL (como ya hiciste) y listo. Verifica que el calljoin del frontend incluya `isAdmin`.

## Nota de seguridad

`isAdmin` viene del cliente, así que un usuario malicioso podría mandar `isAdmin: true`.
Para una app interna/demo es aceptable. Para endurecerlo: verifica el rol contra el API
de monday en el backend usando el token guardado en `monday_credentials`
(`query { users(ids:[<userId>]) { is_admin } }`) en lugar de confiar en el flag del body.

## Toggle opcional

En el paso 2 del `join` (y en `createWorkspace`) uso `onConflictDoNothing`: a un admin
de monday que YA tiene un record (ej. fue puesto como `user` a mano) **no** lo re-promueve,
respetando decisiones manuales. Si prefieres que **todo** admin de monday se fuerce a `admin`
en cada apertura, cambia ese bloque por:

```ts
.onConflictDoUpdate({
  target: [authorizationTable.workspaceId, authorizationTable.userId],
  set: { role: 'admin' }
})
```
